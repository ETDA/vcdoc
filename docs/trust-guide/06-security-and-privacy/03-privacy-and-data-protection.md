# 6.3 ความเป็นส่วนตัวและการคุ้มครองข้อมูล

ต่อจาก [§ 6.2 ข้อกำหนดด้านความปลอดภัย](02-security-requirements.md) บทปิดท้ายของบทที่ 6 นี้อธิบายว่าระบบปกป้องความเป็นส่วนตัวของผู้ถือ VC อย่างไร ครอบคลุมทั้งการเปิดเผยข้อมูลขั้นต่ำ ความยินยอมของผู้ใช้ และฐานทางกฎหมาย

## 6.3 ความเป็นส่วนตัวและการคุ้มครองข้อมูล (เฉพาะของ Trust Framework)

ETDA ยังไม่ได้ออกมาตรฐานความเป็นส่วนตัวฉบับเต็ม ให้ยึดตามที่ OID4VCI และ OID4VP แนะนำเป็นหลัก ด้านล่างคือสิ่งที่ระบบนี้ทำอยู่แล้ว

### 6.3.1 Data Minimization และ Selective Disclosure

- VC ใช้รูปแบบ SD-JWT VC claim ที่อ่อนไหว (เช่น ที่อยู่ รูปภาพ) ถูกซ่อนเป็น digest ใน `_sd` Holder เลือกเปิดเฉพาะ claim ที่จำเป็นผ่าน SD Disclosures
- Verifier ขอ claim ได้เฉพาะที่อยู่ใน `allowed_claims` ของ use case ที่ ETDA อนุมัติ (ดู § 5.3 allowed_claims/allowed_purposes ในตัวอย่าง TL JSON) ขอเกินสิทธิ์ไม่ได้
- ตัวอย่าง: use case สมัครสินเชื่อ (`UC-BBL-LOAN-001`) ขอได้แค่ `citizen_id`, `name_th`, `address` ไม่เห็น `birth_date`

### 6.3.2 ความยินยอมและการควบคุมของผู้ใช้

- ก่อนส่งข้อมูล Wallet แสดง `purpose_th` / `purpose_en` ของ Verifier ให้ผู้ใช้อ่านและกดยินยอม
- Holder เป็นคนเลือกว่าจะแสดง credential ใบไหน (OID4VP) ข้อมูลไม่ออกจาก Wallet ถ้าผู้ใช้ไม่ยินยอม
- Wallet ตรวจว่า Verifier อยู่ใน Trustlist ก่อน (ดู § 4 จุด 2.6) ถ้าไม่ผ่าน หยุดทันที ไม่ส่งข้อมูล

### 6.3.3 Unlinkability / ความเสี่ยง Correlation

- ETDA ยังไม่มีมาตรการเฉพาะเรื่อง unlinkability (เช่น batch issuance เพื่อป้องกันการติดตามข้าม transaction) ให้ยึดแนวทาง SD-JWT VC และ OID4VP

### 6.3.4 ฐานทางกฎหมายและการเก็บข้อมูล

- แต่ละ use case ของ Verifier ต้องระบุวัตถุประสงค์ที่ชัดเจน เช่น "ยืนยันตัวตนตาม พ.ร.บ.ป้องกันฟอกเงิน" (ดู § 5.3 allowed_claims/allowed_purposes ในตัวอย่าง TL JSON) ใช้เป็นฐานทางกฎหมายของการขอข้อมูล
- ETDA ยังไม่ได้กำหนดกฎการเก็บและลบข้อมูล (retention) เฉพาะ Verifier SHOULD เก็บข้อมูลเท่าที่จำเป็นตามวัตถุประสงค์ที่ประกาศไว้เท่านั้น
