# 4.1.1 ขั้นตอนที่ 1 — SETUP, สแกน QR, คำขอฉบับสมบูรณ์, ตรวจ Verifier

## 4.1.1 SETUP, สแกน QR, คำขอฉบับสมบูรณ์ และตรวจ Verifier

#### 🟢 ก่อนเริ่ม — SETUP (ETDA คุม)

ก่อนเริ่มใช้งาน ทั้ง Wallet และ Verifier ต้องดาวน์โหลด **"รายชื่อผู้น่าเชื่อถือ" (Trust list)** จาก ETDA มาเก็บไว้ก่อน (ผ่าน `GET /.well-known/trust-anchor` เพื่อได้ ETDA Public Key และ `GET /trustlist` เพื่อได้ Trustlist) หลักการเหมือนกับ SETUP ในบทการออกเอกสาร (ดู [§ 3.2.2 SETUP](../../03-issuance-flow/02-full-flow/03-setup-and-credential-offer.md#-setup--เตรียมระบบก่อนเริ่มใช้งาน)) ต่างกันตรงที่บทนั้น **Wallet และ Issuer (DOPA)** เป็นผู้ดึง Trustlist ส่วนบทนี้ **Wallet และ Verifier** เป็นผู้ดึงแทน เปรียบเหมือนเจ้าหน้าที่รับบัตรทุกคนต้องมีรายชื่อหน่วยงานและแอปที่ได้รับอนุมัติแล้วก่อนเริ่มงาน

#### 🔵 ขั้นตอนที่ 1 — ผู้ใช้สแกน QR Code

ผู้ใช้สแกน QR Code ที่ปรากฏ ณ จุดให้บริการ กระเป๋าดิจิทัลอ่านข้อมูลเบื้องต้นจาก QR Code เพื่อรู้ช่องทางสำหรับดึงคำขอฉบับสมบูรณ์

#### 🔵 ขั้นตอนที่ 2 — ดึงคำขอฉบับสมบูรณ์

กระเป๋าดิจิทัลส่งคำขอผ่านอินเทอร์เน็ตไปยังผู้ตรวจสอบ (2.5) เพื่อรับคำขอฉบับสมบูรณ์ที่ลงนามแล้ว

🟠 2.6 จุดตรวจสอบที่ 1 — ตรวจสอบความน่าเชื่อถือของ Verifier

**นี่คือจุดควบคุมที่สำคัญที่สุดของฝั่งกระเป๋าดิจิทัล** ก่อนดำเนินการใด ๆ ต่อ กระเป๋าดิจิทัลต้องมั่นใจก่อนว่าผู้ที่ส่งคำขอมาได้รับการรับรองจริง โดยค้นหาว่าผู้ตรวจสอบอยู่ใน Trust list หรือไม่

หากตรวจสอบไม่ผ่าน กระเป๋าดิจิทัลจะยุติกระบวนการทันที

#### 🔵 ขั้นตอนที่ 3 — ส่งเอกสารตอบกลับ

กระเป๋าดิจิทัลส่งเอกสารทั้งหมดไปยังผู้ตรวจสอบ

#### ขั้นตอนที่ 4 — ผู้ตรวจสอบดำเนินการตรวจสอบ

ฝั่งผู้ตรวจสอบเริ่มตรวจสอบเอกสารที่ได้รับ โดยแบ่งเป็นหลายขั้นตอนซ้อนกัน

🟠 4.1 จุดตรวจสอบที่ 2 — ตรวจสอบความน่าเชื่อถือของ Wallet Provider (optional)

ผู้ตรวจสอบยืนยันว่าแอปกระเป๋าดิจิทัลที่ส่งข้อมูลมาเป็นของแท้ โดยค้นหาผู้ให้บริการกระเป๋าดิจิทัลในรายการ Trust list

[บังคับต้องทำเฉพาะ Wallet ของรัฐบาลเท่านั้น]

🟠 4.2 จุดตรวจสอบที่ 3 — ตรวจสอบความน่าเชื่อถือของ Issuer

ผู้ตรวจสอบยืนยันว่าหน่วยงานที่ออกเอกสารได้รับการรับรอง โดยค้นหาผู้ออกเอกสารใน Trust list ตรวจสอบว่าสถานะปัจจุบันยังใช้งานได้ พร้อมตรวจประเภทของเอกสารว่าผู้ออกได้รับอนุญาตให้ออกเอกสารประเภทนี้หรือไม่

ข้างต้นคือคำอธิบายภาพรวมสำหรับผู้อ่านทั่วไป หากต้องการดู **Sequence Diagram ฉบับเทคนิคทั้งหมด** พร้อมคำอธิบายทุก field และทุกขั้นตอนย่อย (สำหรับผู้พัฒนาและสถาปนิกระบบ) ดูได้ที่ [4.2.1 Full Flow เทคนิคโดยละเอียด](../02-full-flow/02b-full-flow-technical-detail.md) — เนื้อหาส่วนนี้ซ่อนโดยดีฟอลต์ ต้องคลิกเพื่อเปิดดู

จบเนื้อหาบทที่ 4 (กระบวนการแสดงเอกสาร) — เมื่อทั้งการออกเอกสาร (บทที่ 3) และการแสดงเอกสาร (บทที่ 4) ผ่านการตรวจสอบครบทุกจุดแล้ว ต่อไปดู [บทที่ 5 โครงสร้างพื้นฐานความน่าเชื่อถือ](../../05-trust-infrastructure/01-technical-requirements-and-schema.md) ว่า Trustlist ที่ใช้ตรวจสอบทั้งสอง flow มีโครงสร้างอย่างไร
